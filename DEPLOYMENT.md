# Deployment & Production Operations Guide

This guide covers deployment instructions, production configuration, credential rotation, database seeding, and troubleshooting for the **StockBros** application.

---

## 1. Production Technology Stack
- **Hosting**: [Vercel](https://vercel.com) (Serverless Next.js App Router)
- **Database**: [Supabase](https://supabase.com) (PostgreSQL with Row Level Security and Realtime enabled)
- **Broker API**: [Angel One SmartAPI](https://smartapi.angelbroking.com/) (For market data and authentication)

---

## 2. Environment Variables Configuration

All secrets must be configured in the **Vercel Project Dashboard** (under Settings > Environment Variables) and never committed to version control.

### Required Environment Variables

| Variable Name | Description | Source / Notes |
| :--- | :--- | :--- |
| `NEXT_PUBLIC_SUPABASE_URL` | The public URL of your Supabase project. | Supabase Dashboard > Settings > API |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY`| The public anon key for frontend queries. | Supabase Dashboard > Settings > API |
| `SUPABASE_SERVICE_ROLE_KEY` | Admin key to bypass Row Level Security. | Supabase Dashboard > Settings > API (Keep Secret) |
| `ANGELONE_API_KEY` | Your SmartAPI Application Key. | Angel One SmartAPI Dashboard |
| `ANGELONE_CLIENT_CODE` | Your Angel One Client ID/Code. | Angel One Account |
| `ANGELONE_PASSWORD` | Your Angel One login MPIN or password. | Angel One Account |
| `ANGELONE_TOTP_SECRET` | The base32 TOTP secret key. | Angel One Security Settings (Keep Secret) |
| `CRON_SECRET` | Secret token generated by Vercel. | Generated automatically by Vercel for Cron protection |

## 3. Angel One TOTP Login & Session Refresh Flow

### How it Behaves in Production
Angel One's SmartAPI requires multi-factor authentication (MFA) via a Time-Based One-Time Password (TOTP) to obtain a Session JWT Token. 
1. **Initial Login**: When the serverless function executes a method requiring historical data, it checks if an in-memory `jwtToken` exists. If not, it generates a current TOTP using the `ANGELONE_TOTP_SECRET` and requests a new token via the login API.
2. **Persistence**: The token is stored as an in-memory variable on the singleton `AngelOneClient` instance. Since Vercel serverless functions persist execution contexts across warm starts, subsequent requests to the same hot lambda instance will reuse the existing token, bypassing the login overhead.
3. **Session Refresh**: If a request fails with an authentication error (token expired, `401 Unauthorized`, or `Invalid Token`), the client catches the error, re-executes `login()` with a newly generated TOTP, and retries the request (up to 2 attempts).

### Rotating Credentials (TOTP Secret or Password)
If you change your Angel One password or regenerate the TOTP secret key:
1. Go to your **Vercel Project Dashboard > Settings > Environment Variables**.
2. Edit `ANGELONE_PASSWORD` and/or `ANGELONE_TOTP_SECRET` with the new values.
3. Save the variables.
4. **Important**: Since environment variables are bound to deployments, you must trigger a new deployment (e.g., redeploy the latest commit) or restart the deployment for the new variables to propagate to active serverless containers.

## 4. Database Seeding & Symbol Syncing

Seeding populates the `symbols` table and fetches 2 years of daily historical data for watchlist and screener analytics.

### Step-by-step Seeding Instructions
To seed your production Supabase database:
1. Update your local `.env.local` file with the **production** Supabase credentials:
   ```env
   NEXT_PUBLIC_SUPABASE_URL=https://your-prod-project.supabase.co
   SUPABASE_SERVICE_ROLE_KEY=your-prod-service-role-key
   ANGELONE_API_KEY=your-prod-api-key
   ANGELONE_CLIENT_CODE=your-prod-client-code
   ANGELONE_PASSWORD=your-prod-password
   ANGELONE_TOTP_SECRET=your-prod-totp-secret
   ```
2. Run the symbol synchronization script to fetch all NSE instruments from Angel One:
   ```bash
   npm run sync-symbols
   ```
3. Run the backfill seeding script:
   ```bash
   npx tsx scripts/seed.ts
   ```
   *Note: This script will backfill 2 years of daily OHLC candle data for the core Nifty index symbols. It handles rate limits automatically.*

## 5. Daily EOD (End of Day) Refresh Cron Job

We use **Vercel Cron Jobs** to update the daily price cache after the Indian stock market closes.

### Configuration (`vercel.json`)
The cron job is configured to hit the secure API endpoint `/api/cron/refresh-eod` at **11:00 AM UTC (4:30 PM IST)** from Monday to Friday:
```json
{
  "crons": [
    {
      "path": "/api/cron/refresh-eod",
      "schedule": "0 11 * * 1-5"
    }
  ]
}
```

### Security
The `/api/cron/refresh-eod` endpoint is protected in production. Vercel automatically attaches `Authorization: Bearer <CRON_SECRET>` when executing cron schedules. Requests without a matching bearer token will be rejected with a `401 Unauthorized` status.

### Checking Cron Job Logs & Troubleshooting
If the daily refresh silently fails or fails to update cached prices:
1. Go to the **Vercel Dashboard > Logs** tab.
2. Select **Cron** in the log category filter, or filter by path `/api/cron/refresh-eod`.
3. Check the logs for:
   - **Status Code**: Ensure the request returned `200 OK`. If it returned `401`, the `CRON_SECRET` headers were missing or mismatched. If it returned `500`, a server error occurred.
   - **Execution Time**: The maximum execution time for serverless functions on Vercel Hobby is 10 seconds. The EOD refresh script only refreshes active watchlist and journal symbols to prevent timeout. If the log shows `FUNCTION_INVOCATION_TIMEOUT`, consider upgrading to a Pro plan or running updates in smaller batches.
   - **SmartAPI Errors**: Look for rate limiting (`429`) or login errors in the console output.
4. Alternatively, open your **Supabase Dashboard > SQL Editor** and verify that new rows have been written to the `price_cache` table for the target trading date:
   ```sql
   SELECT * FROM price_cache ORDER BY created_at DESC LIMIT 10;
   ```
